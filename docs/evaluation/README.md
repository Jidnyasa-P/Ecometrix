# Evaluation (milestone M8)

Automated results are produced by the test suites and the build; the human checks are protocols with templates, because they need people.

## Automated, and what each one proves

| Check | Where | Result at release |
|---|---|---|
| Optimiser equals brute force (16 random instances incl. equity and separation) | `model/tests/test_portfolio.py` | passes |
| Constraints hold on 90 random solves; more budget never means less benefit; shared catchments counted once; hand-worked 3-site case | same | passes |
| Cost, carbon, budget arithmetic against hand-worked values | `backend/tests/test_engine.py` | passes |
| Portfolio totals equal the sum of the same engine's per-site values (base mode) | `model/tests/test_portfolio.py` | passes |
| Pipeline-shaped data → models → API → scenario and portfolios | `backend/tests/test_chain.py` | passes |
| Heat model: spatial CV, ML model kept only when it wins, monotonic check | `model/tests/test_heat_model.py` | passes |
| Forecast: straight-line exactness, backtest picks trend only when it beats "no change", envelope widens | `model/tests/test_forecast.py` | passes |
| Colour contrast ≥ 4.5:1 for all text pairs in both themes; sequential map ramps change steadily in lightness; no font below 13 px; reduced motion | `frontend/src/test/a11y.test.ts` | passes |
| Every screen renders from API fixtures, shows honest empty and error states | `frontend/src/test/*.test.tsx` | passes |

**Real-data results** (cross-validation table, backtest numbers, optimiser gain versus the simple list, sensitivity bars) are generated by each build and shown on the app's *Data audit* and *Evaluation* pages. Copy the numbers into this folder after the first real build and keep disappointing ones.
